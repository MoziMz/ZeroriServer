# 보안 점검 체크리스트

## 안전한 점검 범위

정적 검토와 승인된 비파괴적 검증만 수행한다. 운영 환경에 공격 페이로드를 보내거나,
인증을 우회하거나, 사용자 데이터를 열거하거나, 자격 증명/설정을 변경하지 않는다.

## 인증과 인가

- [ ] 엔드포인트나 접근 규칙 변경 시 `config/SecurityConfig.java`와
  `common/Constant.java`를 함께 읽는다.
- [ ] 새 엔드포인트가 공개, 인증 필요, 사용자 전용, 관리자 전용 중 무엇인지 의도와
  일치하는지 확인한다.
- [ ] 사용자 제공 ID가 인증 사용자 또는 권한 있는 관리자와 비교되는지 확인한다.
- [ ] `security/`의 로그인, remember-me, 로그아웃, 소셜 ID 토큰 변경에서
  토큰/세션 수명주기 회귀를 확인한다.
- [ ] 넓은 경로 매처와 `anyRequest()` 동작 변경은 영향이 크므로, 수정 권고 전 영향
  경로를 정확히 보고한다.

## 입력, 출력, 오류 처리

- [ ] 요청 DTO 검증과 서버 측 비즈니스 검증을 확인한다.
- [ ] 쿼리, URL, 파일 경로, 외부 요청에 쓰이는 경로/쿼리/본문 값의 안전하지 않은
  결합 또는 제약 누락을 확인한다.
- [ ] 오류 응답과 로그가 스택 트레이스, 비밀값, 개인정보를 노출하지 않는지 확인한다.
- [ ] 가용성에 영향을 줄 수 있는 페이지, 정렬, 필터 입력에 적절한 상한이 있는지
  확인한다.

## 파일 업로드와 S3

- [ ] 각 `MultipartFile` 엔드포인트에서 Service와 S3 업로드 경로까지 추적한다.
- [ ] 서버 측 콘텐츠 탐지와 MIME 허용 목록을 사용하는지 확인한다. 현재 이미지 처리는
  Tika와 `Constant`의 허용 목록을 사용한다.
- [ ] 설정된 요청/파일 크기 제한이 요구사항에 맞는지 확인한다.
- [ ] 오브젝트 키와 폴더에 예측 가능하거나 사용자 제어 경로 요소가 없는지 확인한다.
- [ ] 버킷 또는 ACL 설정 변경 시 업로드 객체 접근과 메타데이터 동작을 검토한다.

## 비밀값, 설정, 의존성

- [ ] 비밀값이 환경 변수로 관리되고, 소스/문서/로그/생성 보고서에 커밋되지 않는지
  확인한다.
- [ ] DB, 메일, JWT, AWS, 소셜 로그인, Sentry, Slack, GitHub Models 설정 변경에서
  비밀값 노출 또는 안전하지 않은 기본값을 검토한다.
- [ ] 의존성 업그레이드가 보안 동작에 미치는 영향을 검토하고, 인증과 핵심 API 테스트가
  유지되는지 확인한다.
- [ ] 해석된 애플리케이션 설정 값을 보고서에 출력하지 않는다.

## 로깅과 모니터링

- [ ] `ApiLogFilter` 변경 시 새 요청/응답 필드나 마스킹 범위 축소가 없는지 확인한다.
- [ ] 요청/오류 응답 본문은 기본적으로 민감정보로 취급한다. 현재 명시적 마스킹 필드는
  `pw`, `currentPw`뿐이다.
- [ ] 사고 보고서에서 사용자 식별자, IP, 토큰, 본문을 마스킹한다.
- [ ] Sentry 또는 Slack 알림 변경이 민감정보를 전송하지 않는지 확인한다.

## 발견 사항 형식과 대응 우선순위

`agent-operating-rules.md`의 공통 형식을 사용하고, 보안 이슈에는 다음 항목을
추가한다.

```text
공격 전제조건: 필요한 접근 권한 또는 입력
영향 표면: 엔드포인트, 설정, 또는 컴포넌트
잠재 영향: 기밀성, 무결성, 가용성, 또는 인가
안전한 검증: 정적 근거 또는 승인된 비파괴적 확인
개선 방안: 위험을 줄이는 가장 작은 구체적 변경
```

`critical`, `high` 이슈는 적용 전 담당자 검토가 필요하다. 노출이 진행 중일 수
있으면 완화를 먼저 권고하고, 이후 수정과 재검증을 제안한다. 근거 없이 실제 악용
가능성을 단정하지 않는다.

## 정적 검증 예시

`SecurityConfig`를 검토할 때는 요청 매처의 순서와 의도를 확인하고, 변경된
Controller 경로를 해당 상수와 비교한다. 공개 경로라는 사실만으로 문제라고 하지
않으며, 코드나 제품 의도가 인증 필요를 가리킬 때만 발견 사항으로 보고한다.
