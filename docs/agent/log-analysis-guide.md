# 로그 분석 가이드

## 입력과 범위

익명화된 로그 샘플 또는 승인된 읽기 전용 로그 소스만 분석한다. API 로그 형식은
`src/main/java/com/mozi/moziserver/log/ApiLogFilter.java`가 만든다. 요청 파라미터와
오류 응답 본문은 검토와 마스킹 전에는 보고서에 포함하지 않는다.

## API 로그 필드

| 필드 | 의미 | 분석 용도 |
| --- | --- | --- |
| `time` | Asia/Seoul 기준 요청 시작 시각 | 타임라인과 사고 구간 |
| `profiles` | 활성 Spring 프로필 | 환경 분리 |
| `threadId` | 요청별 상관관계 ID | 개별 요청 이벤트 추적 |
| `duration` | 요청 처리 시간(ms) | 느린 요청 순위화 |
| `method`, `path`, `patternPath` | HTTP 메서드, 실제/템플릿 경로 | 엔드포인트 그룹화 |
| `statusCode` | HTTP 상태 코드 | 오류율 그룹화 |
| `userSeq` | 인증된 사용자 식별자, 존재할 때만 기록 | 익명화한 상관관계 분석 |
| `userIp`, `userAgent` | 클라이언트 메타데이터 | 마스킹 후 패턴 진단 |
| `reqParam`, `resBody` | 캐시된 요청/오류 응답 내용 | 민감정보로 취급 |

`ApiLogFilter`는 `/api/health-check`를 제외하고 POST, PUT 요청 본문을 기록한다.
현재 명시적으로 마스킹하는 JSON 필드는 `pw`, `currentPw`뿐이므로, 나머지 본문도
민감할 수 있다고 가정한다.

## 탐지 기준

아래 기준은 조사 후보를 찾기 위한 것이며, 그 자체로 장애 원인 확정은 아니다.

| 신호 | 후보 조건 | 필요한 후속 확인 |
| --- | --- | --- |
| 서버 오류 | `patternPath` 기준 5xx 응답 존재 | 예외와 대상 API 코드 확인 |
| 클라이언트 오류 급증 | 분석 구간에 같은 `patternPath`의 4xx가 반복 | 정상 검증 실패와 인증/계약 회귀 분리 |
| 느린 요청 | `duration` 상위 요청을 엔드포인트별로 정렬 | 기준선을 만든 뒤 DB/외부 호출 경로 확인 |
| 반복 실패 | 짧은 구간에 같은 경로/상태 패턴 반복 | 배포 시각, 외부 의존성, 익명화된 클라이언트 패턴 확인 |
| 넓은 영향 | 여러 경로가 실패하거나 공통 의존성이 보임 | Sentry, Slack, DB, 외부 클라이언트 상태 확인 |

승인된 운영 목적과 마스킹 없이 `userSeq`, IP, User-Agent만으로 사용자 단위 패턴을
추정하지 않는다.

## 분석 절차

1. 시간 범위를 제한하고 `profiles`로 환경을 나눈다.
2. `patternPath`, `method`, `statusCode`로 그룹화한다. 경로 파라미터 때문에 결과가
   분산되므로 원본 `path`만으로 그룹화하지 않는다.
3. 5xx, 반복 4xx, 높은 `duration` 그룹을 빈도와 영향 범위 순으로 정렬한다.
4. 대표 `threadId` 소수만 선택해 익명화된 근거를 확인한다.
5. 원인을 언급하기 전 해당 Controller, Service, Repository, 외부 Client를 읽는다.
6. 공통 운영 규칙에 따라 사실, 근거, 판단, 권장 조치를 구분해 보고한다.

## 보고 형식

```text
사고 구간: 2026-01-01 10:00-10:30 KST
심각도: high
신호: POST /api/*/example의 5xx 증가
사실: 선택한 구간에서 12건이 500으로 응답했다.
근거: 익명화한 thread ID와 상태 코드 집계.
영향: 해당 요청을 완료할 수 없다.
판단: 의존성 또는 애플리케이션 오류 가능성이 있으며 예외 상관관계 확인이 필요하다.
권장 조치: 관련 예외, 최근 배포, 의존성 상태를 확인한다.
확신도: needs-verification
```

## 익명화된 검증 예시

입력 요약: `POST /api/*/confirms`가 10분 동안 3회 500을 반환했고, 처리 시간은
120 ms, 140 ms, 135 ms이다.

기대 결과: 반복된 5xx 그룹으로 보고하고, 모든 ID와 본문을 마스킹한다. 원인을
단정하지 않고 Controller/Service 예외 경로와 S3 또는 외부 의존성 근거를 확인하도록
권고한다.
