# 에이전트 운영 규칙

## 작업 범위와 읽는 순서

모든 작업 전에 `project-context.md`를 읽는다. 이후 작업별 가이드를 읽고, 판단에
필요한 코드, 설정, diff, 로그만 추가로 확인한다.

| 작업 | 필수 가이드 | 주요 근거 |
| --- | --- | --- |
| 로그 분석 | `log-analysis-guide.md` | 익명화된 API 로그, `ApiLogFilter.java`, 영향 API 코드 |
| 코드 리뷰 | `code-review-guide.md` | Git diff, 변경 파일, 연결된 호출부와 테스트 |
| 보안 점검 | `security-checklist.md` | 보안/설정 코드, 변경 엔드포인트, 업로드·외부 연동 경로 |
| 문서 정리 | `documentation-guide.md` | 현재 코드, 빌드 파일, 실행 설정, 기존 문서 |

코드 리뷰에서는 `.github/CONVENTION/`이 프로젝트 컨벤션의 원본이다. 스타일이나
멤버 순서를 지적하기 전에는 변경 계층에 맞는 컨벤션 문서를 읽는다.

## 근거 기반 보고

모든 결론을 아래 세 부분으로 구분한다.

- **사실:** 파일 경로, 라인, 로그 필드 등으로 직접 확인한 동작이나 설정
- **근거:** 사실을 뒷받침하는 diff, 코드 경로, 설정, 익명화된 로그 이벤트
- **판단:** 위험도, 추정 원인, 해석. 확인된 사실처럼 표현하지 않는다.

발견 사항은 아래 형식을 사용한다.

```text
심각도: high | medium | low | info
제목: 짧은 설명
사실: 확인된 관찰 내용
근거: 파일/로그 참조
영향: 영향받는 동작 또는 노출 범위
권장 조치: 구체적인 다음 행동
확신도: confirmed | likely | needs-verification
```

## 민감정보 처리

다음 값은 프롬프트, 보고서, 코멘트, 생성 문서에 원문으로 재현하거나 저장하지
않는다.

- 비밀번호, 비밀번호 재설정값, 액세스 토큰, API 키, JWT, 세션 ID, 쿠키,
  Authorization 헤더, 개인 키, 웹훅 URL
- DB, 메일, 클라우드, 소셜 로그인, Sentry, Slack, GitHub Models의 비밀값
- 개인정보가 포함될 수 있는 전체 요청/응답 본문
- 사고 설명에 꼭 필요하지 않은 이메일, IP, 기기 식별자, 사용자 ID 등 식별값

`[REDACTED]`, `user-***`, `ip-***` 같은 형태로 대체한다. 원시 로그의 필드 의미를
모르면 검토 전까지 민감정보로 취급한다.

## 안전한 행동 원칙

- 기본 행동은 분석과 권고이며, 운영 설정, 자격 증명, 권한, 사용자 데이터, 배포
  설정을 변경하지 않는다.
- `high` 또는 `critical` 보안 이슈는 근거, 영향, 완화 또는 수정 권고를 먼저
  보고하고 자동 수정하지 않는다.
- 안전하고 승인된 테스트나 직접 근거가 없으면 재현 가능 또는 취약하다고 단정하지
  않는다.
- 명시적 승인 없이 능동적 공격, 파괴적 테스트, 운영 환경에 영향을 주는 스캔을
  수행하지 않는다.
- 실행 환경 정보가 부족하면 추측하지 말고 추가로 확인할 대상과 방법을 적는다.

## 심각도 기준

| 심각도 | 의미 |
| --- | --- |
| critical | 넓은 범위의 침해, 정보 노출, 서비스 영향이 즉시 발생할 수 있고 근거가 강한 경우 |
| high | 빠른 담당자 검토가 필요한 중대한 보안, 정확성, 가용성 위험 |
| medium | 영향이 제한적이거나 추가 조건이 필요한 실질적 결함 또는 약점 |
| low | 영향이 작거나 하드닝 성격의 결함, 유지보수 이슈 |
| info | 확인된 문제 없이 맥락이나 추가 검증이 필요한 관찰 |
